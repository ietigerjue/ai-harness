## 1. 三层记忆体系

```

┌─────────────────────────────────────┐
│           长期记忆 (Long-Term)        │
│  稳定规则、项目总结、复用工作流、技术栈  │
│  生命周期：永久保留                    │
│  存放位置：                            │
│  • 00_总索引/ (规则文件)               │
│  • 02_工作流沉淀/ (工作流)             │
│  • 04_归档项目/ (项目总结)             │
└─────────────────────────────────────┘
              ▲
              │ 归档完成后提取
              │
┌─────────────────────────────────────┐
│           中期记忆 (Mid-Term)         │
│  当前项目状态、Handoff、任务进度        │
│  生命周期：项目进行中                   │
│  存放位置：                            │
│  • 01_项目记录/ (项目记录文件)          │
│  • 05_可回溯记录/ (决策/变更记录)       │
└─────────────────────────────────────┘
              ▲
              │ 验证后提升
              │
┌─────────────────────────────────────┐
│           短期记忆 (Short-Term)        │
│  临时错误日志、一次性命令输出、调试碎片   │
│  生命周期：会话结束后清理               │
│  存放位置：                            │
│  • 不存入记忆库                        │
│  • 仅在会话上下文中存在                  │
└─────────────────────────────────────┘

```

## 2. 核心规则

### 规则一：临时错误日志不得直接进入总索引

- ❌ 禁止：把一次性的编译错误日志写入 `00_总索引/`
- ❌ 禁止：把调试过程中的碎片信息写入项目记录文件
- ✅ 正确：错误解决后，总结为一条"问题与解决方案"记录
- ✅ 正确：临时错误仅保留在项目记录文件的执行日志表中

### 规则二：未验证的信息不得进入工作流沉淀

- ❌ 禁止：把假设的、未经过项目验证的工作流写入 `02_工作流沉淀/`
- ✅ 正确：工作流必须来自真实完成的项目
- ✅ 正确：如果推测某工作流可能有用，标记为"待验证"并单独记录

### 规则三：只有完成归档的项目才能进入长期工作流沉淀

- ❌ 禁止：项目进行到一半就提取工作流
- ✅ 正确：项目必须走完 Idea → Archive → Workflow Extraction 全流程
- ✅ 正确：Workflow Extraction 在 Archive 之后执行

### 规则四：执行日志可以详细，但项目总结必须压缩、结构化

- 执行日志（`05_可回溯记录/执行日志/`）：可以详细记录每次操作
- 项目总结（`04_归档项目/`）：必须结构化、压缩、可检索
- 原则：执行日志是"流水账"，项目总结是"浓缩版"

### 规则五：不确定信息必须标记"未确认"

- 任何无法从现有文件或记录中确认的信息 → 标记"未确认"
- 任何需要用户补充的信息 → 标记"需要用户补充确认"
- 任何推测性内容 → 标记"推测，待验证"

### 规则六：重复内容应合并

- 同一信息不应在多个文件中重复出现
- 应该是一个权威源 + 其他文件引用
- 示例：项目版本号 → 只有项目记录文件中有完整记录，索引文件只引用

### 规则七：所有项目记录必须通过项目总索引可找到

- `00_总索引/项目总索引.md` 是全量索引
- 任何项目记录文件必须在项目总索引中有条目
- 没有孤儿文件

## 3. 信息写入决策树

```

新信息产生
    │
    ├─ 是临时错误/一次性输出？
    │   └─ YES → 不存入记忆库（会话内处理）
    │
    ├─ 是项目执行记录？
    │   └─ YES → 写入 01_项目记录/ 对应项目文件
    │       └─ 同时更新 00_总索引/项目总索引.md
    │
    ├─ 是重要决策？
    │   └─ YES → 写入 05_可回溯记录/决策记录/
    │       └─ 同时在项目记录文件的决策记录表中记录
    │
    ├─ 是可复用工作流？
    │   └─ YES → 项目归档后写入 02_工作流沉淀/
    │       └─ 仅从已完成项目中提取
    │
    ├─ 是全局规则？
    │   └─ YES → 写入 00_总索引/
    │       └─ 轻量更新可追加，重大修改需用户确认
    │
    └─ 无法确定？
        └─ 先写入项目记录文件的备注区
            └─ 标记"待分类"，后续再归档
```

## 4. 记忆库污染检查清单

每次写入记忆库前自查：

- [ ] 这条信息是永久的还是临时的？
- [ ] 这条信息是否已被验证？
- [ ] 这条信息是否已经在其他文件中存在？
- [ ] 这条信息属于哪个记忆层级（长期/中期/短期）？
- [ ] 这条信息是否带有正确的"未确认"标记？
- [ ] 这条信息能否通过项目总索引找到？
- [ ] 这条信息是否包含敏感数据（API Key、密码等）？

## 5. 清理规则

### 可以清理的内容

| 内容 | 清理时机 | 清理方式 |
|---|---|---|
| 会话级临时输出 | 会话结束 | 不保存 |
| 已解决的错误日志 | 项目归档时 | 压缩为一句话总结 |
| 过时的推测 | 验证后 | 替换为确认信息 |
| 重复内容 | 发现时 | 合并到权威源 |

### 绝对不能清理的内容

| 内容 | 原因 |
|---|---|
| 项目执行日志 | 可回溯 |
| 决策记录 | 可回溯 |
| 回滚点 | 可恢复 |
| 归档项目总结 | 长期参考 |
| 工作流沉淀 | 复用价值 |
