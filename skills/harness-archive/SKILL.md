# 归档项目

## 触发条件

用户说"项目归档" / "archive" / "项目完成" / "结束" / "总结" + 项目名称。

## 前置条件

- 项目已通过 Review 阶段（Done Criteria 检查完毕）
- 项目记录文件存在

---

## 执行流程

### Step 1: 确认要归档的项目

如果用户没有指定项目名，列出 `01_项目记录/` 下所有处于 Review 状态的项目让用户选择。

### Step 2: 读取项目材料

1. 读取项目记录文件（`01_项目记录/{领域}/{项目文件}.md`）
2. 如果项目有代码仓库，读取关键文件（README、package.json、目录结构等）
3. 搜索 `design.md`（在项目路径和项目记录附近）
4. 读取 `docs/` 下的关键文档（如 project-state.md、decisions.md）

### Step 3: 总结项目真实历史

基于实际读取的内容（不是编造的），整理：

- 开发起止时间（从 git log 或文件时间戳）
- 关键里程碑（从 git log、change-log、决策记录）
- 版本演进（从 v0.1 到 v1.0 的实际路径）
- 技术栈（从 package.json / 代码实际使用的）
- 已知限制（从 project-state.md 或文档）

### Step 4: 判断项目类型

- **WebApp**：有前端+后端，部署为 Web 服务
- **App**：移动端或桌面应用
- **Skill**：ClaudeCode/Codex 的 Skill 插件
- **嵌入式开发**：涉及硬件/固件
- **机器学习**：ML/DL 建模、数据分析

### Step 5: 创建归档目录和文件

创建 `04_归档项目/{类型}/{归档日期} {项目名称}/`，写入 `归档总结.md`：

```markdown
# {项目名称} — 归档总结

**归档日期**：{date}
**项目类型**：{type}
**项目路径**：{path}
**版本**：v1.0

### Step 6: 更新项目记录文件

在原项目记录文件中追加归档摘要区块：

```markdown
## 项目归档摘要

{date} 归档。

{总结段落}

详见归档目录：`04_归档项目/{类型}/{归档日期} {项目名称}/`
```

### Step 7: 更新全部索引

1. `00_总索引/项目总索引.md` — 将项目状态更新为"已归档 v1.0"
2. `00_总索引/回滚与版本记录.md` — 新增项目回滚点汇总
3. `00_总索引/MEMORY.md` — 新增归档条目索引
4. `02_工作流沉淀/{类型}工作流.md` — 追加工作流模式和经验教训（只追加不覆盖）
5. `02_工作流沉淀/技术栈积累.md` — 追加项目中新使用的技术栈

```

项目已从 Review → Archive，版本 v1.0。
```
