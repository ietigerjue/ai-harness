# 新建项目记录

## 触发条件

用户说"新建项目 {名称}" / "new project" / "创建项目记录"。

## 前置条件

已运行 `harness-init`，记忆库目录结构存在。

---

## 执行流程

### Step 1: 收集项目信息

如果用户没有提供完整信息，依次询问：

1. **项目名称** — 简短明确的项目名
2. **所属领域** — 从 `01_项目记录/` 下的子目录列表中选择（读取实际存在的领域目录）
3. **项目类型** — WebApp / App / Skill / 嵌入式开发 / 机器学习
4. **项目路径** — 代码或项目文件在磁盘上的位置（可选，暂时可留空）
5. **一句话目标** — 这个项目要做什么

如果用户一句话说清楚了（如"新建项目 UST Buddy，副业，WebApp"），直接使用，不重复询问。

### Step 2: 检查是否已存在

检查 `01_项目记录/{领域}/` 下是否已有同名或类似项目记录。如果已存在，提示用户：

```
⚠️ {领域} 下已存在项目记录：{文件名}
如果这是同一个项目，不要创建新文件。直接更新已有记录即可。
是否继续创建新项目？(y/N)
```

### Step 3: 按模板创建项目记录文件

从 `07_模板库/项目记录模板.md` 复制并填充：

```markdown
# {日期} {项目名称}

## 1. 项目基本信息

- 项目名称：{name}
- 所属领域：{domain}
- 项目类型：{type}
- 当前状态：Idea/Brainstorm（v0.1）
- 项目路径：{path}
- 创建日期：{date}
- 最后更新：{date}
- 当前版本：v0.1

## 2. 项目目标

{goal}

## 3. 项目状态机

- 当前状态：Idea/Brainstorm
- 上一个状态：—
- 下一状态：Spec
- 状态变更时间：{date}
- 状态变更原因：项目新建
- 执行 Agent：ClaudeCode

## 4. Agent 分工记录表

| 日期 | 执行 Agent | 任务 | 状态 | 产出 | 备注 |
|---|---|---|---|---|---|
| {date} | ClaudeCode | 项目创建 | 已完成 | 项目记录文件 | 初始化 |

(后续记录追加在此)

## 5. 需求变化表

| 日期 | 变更内容 | 影响 TASK | 处理方式 | 执行 Agent |
|---|---|---|---|---|

## 6. 决策记录表

| 日期 | 决策内容 | 原因 | 影响范围 | 执行 Agent |
|---|---|---|---|---|

## 7. 当前进度

- 已完成：项目记录已创建
- 进行中：需求分析
- 待处理：技术方案设计、任务拆解
- 阻塞点：无

## 8. 可回溯执行日志

| 日期 | Agent | 操作 | 结果 | 备注 |
|---|---|---|---|---|

## 9. 回滚点

| 日期 | 回滚点名称 | 涉及文件 | 回滚说明 |
|---|---|---|---|

## 10. 项目完成检查（Done Criteria）

- [ ] 项目目标已明确
- [ ] 核心任务已完成
- [ ] 关键文件已生成或更新
- [ ] 测试或人工验证已完成
- [ ] 项目记录已更新
- [ ] design.md 已检查
- [ ] Skill 产物已归类
- [ ] 回滚点已记录
- [ ] 工作流沉淀已更新
- [ ] 项目总索引已更新
```

### Step 4: 更新索引

在 `00_总索引/项目总索引.md` 的对应领域表格中添加一行：

```markdown
| {项目名称} | {类型} | Idea/Brainstorm (v0.1) | [../01_项目记录/{领域}/{文件名}](file) | {date} | {date} |
```

### Step 5: 输出创建结果

```
✅ 项目记录已创建！

文件：01_项目记录/{领域}/{日期} {项目名称}.md
状态：Idea/Brainstorm (v0.1)
下一步：ClaudeCode 可以开始需求分析和方案设计
```
