# Done Criteria 模板

> **用途**: 防止把"计划完成"误判为"项目完成"。在 Review 阶段逐项检查。
>
> **使用方式**: 复制对应类型的 Done Criteria 到项目记录文件，逐项勾选。

---

## 一、通用 Done Criteria

所有项目类型都必须满足：

- [ ] 项目目标已明确
- [ ] 核心任务已完成
- [ ] 关键文件已生成或更新
- [ ] 测试或人工验证已完成
- [ ] 项目记录已更新
- [ ] NEXT_ACTIONS 已清理或转入后续计划
- [ ] design.md 已检查，存在则归档，不存在则明确记录
- [ ] Skill 产物已归类
- [ ] 回滚点已记录
- [ ] 工作流沉淀已更新
- [ ] 项目总索引已更新

---

## 二、WebApp Done Criteria

在通用标准基础上增加：

- [ ] 前端页面可正常加载
- [ ] 后端 API 可正常响应
- [ ] 核心用户流程可走通（happy path）
- [ ] 错误状态有处理（error/empty/loading）
- [ ] 环境变量和密钥未提交到 Git
- [ ] 如有部署：部署地址可访问
- [ ] README 包含启动说明

- [ ] 如有发布：包体可正常安装

---

## 七、使用指南

### 使用时机

在项目状态机的 **Review** 阶段使用此模板。

### 检查方式

1. 将对应类型的 Done Criteria 复制到项目记录文件中
2. 逐项检查，已完成的打勾
3. 未完成的项目标记为阻塞项，转入 NEXT_ACTIONS
4. 全部完成后才可进入 Archive 阶段

### 特殊情况的处理

| 情况 | 处理方式 |
|---|---|
| 某项不适用 | 标记为 N/A 并说明原因 |
| 某项无法确认 | 标记为"未确认"并说明需要什么信息 |
| 某项需要用户确认 | 标记为"待用户确认"，不勾选 |
